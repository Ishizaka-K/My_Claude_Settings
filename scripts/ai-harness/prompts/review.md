# Goal

入力ファイルだけを根拠に、設計、タスク、実装の問題をレビューしてください。

このレビューの主体は Codex です。Claude はレビュー結果を整理し、修正指示をCodex workerへ返し、再レビューとユーザー報告を行います。

# Context

このプロンプトの後に、レビュー対象の設計書、タスク、diff、テスト結果などが添付されます。

前工程の会話コンテキスト、Claude の思考過程、未添付の外部情報は根拠にしないでください。

# Constraints

- あなたは独立したレビューアです。
- 入力ファイルだけを根拠にしてください。
- コード変更は行わないでください。
- 好みの違いだけを重大指摘にしないでください。
- すべての Findings に具体的な修正案を含めてください。
- 可能であれば、修正前後のコード例、設計書の追記案、タスク記述の修正案、または Unified Diff Patch 案を示してください。

# Review Policy

- High は、次工程に進むと正しさ、動作、安全性が保証できない問題に限定する。
- Medium は、手戻り、保守性低下、仕様ずれ、テスト不足につながる問題に使う。
- Low は、命名、読みやすさ、軽微な整理、将来の改善に使う。
- 好みの違いだけを重大指摘にしない。
- 指摘には根拠、影響、修正案を含める。

# Done when

- Findings が重要度順に整理されている。
- 各指摘に根拠、影響、修正案がある。
- 修正案が、Claude がそのまま実行または設計書/Task へ反映できる具体度になっている。
- Open Questions が整理されている。
- Verdict が `proceed` または `revise` で示されている。

# Output format

```md
## Findings

- [High|Medium|Low] <title>
  - 根拠:
  - 影響:
  - 修正案:
  - 修正例:

## Open Questions

## Verdict

- proceed / revise
```
